# addpixel 对照实验结论（20261106）

## 实验定位

`ovf_gae_re10k_patch1_addpixel`（配置：`train_config/normal_config/gae_ovf_re10k_patch1_addpixel.yaml`）
是 `concatpixel` 的解耦对照臂：与 `gae_ovf_re10k_patch1_concatpixel.yaml` 逐位一致，
唯一变量组为 `view_condition_mode: "concat" -> "add"`。

- **add**：Plucker 射线场经 ViewConditionEncoder 小 CNN 瓶颈
  （1x1: 1176+8role -> 64 -> 3x3 -> 64 -> 1x1 -> 64，末层零初始化）后，
  `z + view_condition` 加性注入；
- **pixel**：Plucker 按 pixel 分辨率无损栅格化（PixelUnshuffle，6×14²=1176ch），
  与 concatpixel 相同。

协议：8 场景 overfit、seed 42、无 camera drop、bs4×accum1×2 NPU = 有效 batch 8。

## 结果

同 8 场景、同 seed、同 eval 样本（两边日志 `src_depth_abs_rel=0.2037` 完全一致，可证样本相同）：

| step | concatpixel（PSNR / d1 / lpips） | addpixel（PSNR / d1 / lpips） |
|---|---|---|
| 200  | 14.15 / 0.42 / 0.74 | 13.85 / 0.40 / 0.63 |
| 600  | 16.75 / 0.80 / 0.47 | 14.05 / 0.52 / 0.54 |
| 1000 | 17.63 / 0.81 / 0.41 | 13.38 / 0.51 / 0.58 |
| 2000 | 19.22 / 0.89 / 0.31 | 13.48 / 0.50 / 0.56 |
| 2200 | **19.58 / 0.91 / 0.29** | 13.36 / 0.46 / 0.58 |
| 5400 | —（早收敛）          | 13.51 / 0.50 / 0.55 |
| 5600 | —                    | 13.50 / 0.48 / 0.56 |

关键事实：**addpixel 从未收敛**。

- eval 指标从 step 200 起纹丝不动（PSNR ~13.5、d1 ~0.46、lpips ~0.57），直到 5600 步；
- train loss 卡在 0.22~0.41，无法继续下降；
- 8 个场景的 overfit 都做不到，而 concatpixel 2000 步即接近记住该子集。

轨迹测试（`tools/traj_addpixel_5400.sh`，step-5400，scene 00028da87cc5a4c4，21 帧）：
PSNR 12.53 / lpips 0.547 / d1 0.442 / aligned rel 0.437——作为 overfit 模型在自己训练场景上
仍是垃圾水平（对照：nearest_src_psnr 基线 10.34，仅高出 ~2dB）。

## 与 `gae_patch1_re10k20261103_145404` 的关系

该 run 是 **add + latent 分辨率** Plucker、**全量 re10k（7884 场景）** 的训练
（日志：`ViewConditionEncoder: mode=add plucker_resolution=latent pixel_scale=8`），
从更早 run 的 step-3300 resume 至 8700。

- 它的 eval 8 样本与 addpixel 的 8 场景 overfit 集**不是同一批**，绝对数值不可直接比
  （其 eval PSNR 11.2~12.4 / d1 0.48~0.59，表面低于 addpixel，但 eval 集不同、难度不同）；
- 视觉上它更稳：它是在够大数据上正常收敛的模型；而 addpixel 是连 8 个场景都没记住的模型。
  二者的差距本质是"收敛 vs 不收敛"，而非数据量或分辨率本身。

## 判读（命中 yaml 预设判读标准第 2 分支）

按 `gae_ovf_re10k_patch1_addpixel.yaml` 头部判读标准：

> add+pixel 仍显著落后 → **concat 注入本身有优势**（无瓶颈、不扰动输入 latent、每通道独立权重）。

病因分析（指向 add 注入路径）：

1. **信息瓶颈**：1176ch Plucker + 8 role 压到 64ch 再加到 z，容量太窄，相机信号送不进去；
2. **扰动预训练分布**：加性注入改变了 DiT 预训练 latent 的输入统计，模型倾向把它当噪声忽略；
   零初始化输出层使训练初期相机信号恒为零，梯度需穿过窄瓶颈才能建立响应；
3. **concat 的优势**：不动 z（不扰动输入分布）、每通道独立权重、无瓶颈。

## 结论

- pixel 无损栅格化（14x，1176ch）是必要条件，但**必须配 concat（无损直通）注入**；
  add 瓶颈路径会彻底废掉相机控制能力。
- 后续实验（`geo_color_token_ovf_re10k_lora_pixel14.yaml`）沿用 pixel14 无损栅格化，
  并注明"addpixel 实验已证明 pixel 无损栅格化是赢家，注入方式次要"——
  严格表述应为：**栅格化分辨率重要，但注入方式（concat vs add）在同一栅格化下是主要分化项**。
